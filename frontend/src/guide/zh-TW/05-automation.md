# 自動化、整合與 agent

## 規則

![工作流程規則](/guide/13-workflow-rules.png)

一條規則由觸發、條件、動作組成。觸發是**圖的形狀**而不是任務的形狀：
`node.created`、`node.updated`、`node.deleted`、`edge.added`、`edge.removed`——
所以規則可以對「一條關係被建立」反應，不只是對某個欄位改變反應。
條件可以比對*改變了什麼*，不只是比對主體。

規則不會連鎖。規則做的每一次寫入都會回到同一條流水線，但關掉規則觸發，
所以一條規則不會引發另一條規則。

存檔前的試跑會拿你真實的資料，顯示這條規則實際上會做什麼。

## 整合

![整合](/guide/14-integrations.png)

出站：webhook（用 HMAC-SHA256 簽章）與 email。每一次嘗試都會記錄，並有重試退避，
因為 webhook 的失敗形式是「安靜」。

入站：任務會有一個回呼位址給 CI/CD 打。GitHub、GitLab、Jenkins、Drone、Bitbucket
的 payload 都會被辨識並正規化。

**憑證不會離開伺服器。** 已儲存的密鑰讀回來是 `null`，但鍵還在；而送出 `null` 代表
「不變」——所以你可以取回一份設定、改其中一個欄位、再送回去，而不會毀掉一個
你從來沒看過的憑證。

## 助理

![助理](/guide/12-assistant.png)

助理透過一組工具讀寫你真正的資料。provider 是執行期設定而不是建置期設定：
指向 Claude、指向 OpenAI、或指向任何講這兩種協定的端點，改完下一則訊息就生效。

## Agent 與 API

你在瀏覽器裡能做的每一件事，agent 都能用 API 金鑰透過 `/api/v1` 做，或透過 MCP 做。
這是程式碼用測試強制的規則，不是願望——一個只有「坐在瀏覽器前的人」才碰得到的能力，
在這裡被當成缺陷。

![設定](/guide/18-settings.png)

金鑰的**範圍**界定了它能做什麼：`read`、`write`、`admin`。
金鑰也可以綁定到單一容器，那就把它限制在該容器的子樹裡。
