# 決策

決策紀錄回答的是「為什麼會是這樣？」——這個問題在任務清單裡沒有家，
而且往往幾個月後由一個當時不在場的人問出來。

![決策室](/guide/10-decisions.png)

決策是自己的一種節點型別，所以它帶著自己的關係：

- **`supersedes`**——這筆取代那筆。記下這條邊的同時也會讓另一端退役，
  因為「這條邊」和「那端的狀態改變」是同一個動作。
- **`governs`**——這筆決策決定了那件工作。方向是刻意的：
  任務不是*被貼上*決策的標籤，是決策*決定*了任務。
- **`requires`**——這筆只在那筆成立時才成立。反過來讀，回答的是
  「如果這個前提被重新打開，什麼會垮掉？」
- **`conflicts_with`**——這兩筆互相矛盾。它是對稱的：從任一端寫都是同一條邊，
  而且兩端都會報出來。

矛盾是一個問題，不是一個判決。要解決它就去 supersede 其中一邊，
絕不是刪掉任何一邊——所以這裡沒有「解決」按鈕。

## 依所在位置歸檔，也可以畫成圖

紀錄依照它們的所在階層分組，所以一個裝著四個專案的組織是一列，不是四列。
太大的區段預設收起來。

圖形檢視不是力導向佈局——位置本身就是方向性問題的答案。第 0 欄是基礎；
順著箭頭往右走，就是從前提走到結論；被治理的工作在下方。
選一個節點會把跟它無關的都調暗，旁邊出現的是清單畫的同一張卡片，
所以「發現少了一條邊」和「把它補上」是同一個畫面。

關係靠線條樣式與符號區分，不靠顏色，因為這一頁的顏色留給狀態。
