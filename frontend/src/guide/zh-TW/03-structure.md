# 結構：工作住在哪裡

每樣東西都是節點，而連接它們的關係有兩種。把這兩種分清楚，是這個產品裡最有用的一個觀念。

- **`contains`**——*節點住在哪裡*。組織裝著身分，身分裝著專案，專案裝著任務。
  所有的統計與進度都沿著這條關係往上加總。
- **`owns`**——*它是誰的*。身分擁有容器。它完全不說明工作坐落在哪裡。

把後者折進前者，會讓「擁有」讀起來像多了一層「包含」，所以它們是兩條分開的軸。

如果篩選把父節點藏起來，它的子節點會被提升到頂層，而不是跟著消失。

## 一個專案有多大？

只有一個定義，到處都一樣：**它整個 `contains` 子樹裡的頂層任務數**。
專案頁、搜尋、分享頁、API、通知信、助理，讀的都是同一個數字。
如果有兩個畫面對同一個專案的大小講法不同，那是 bug，不是見解不同。

## 項目型別

![項目型別](/guide/16-item-types.png)

節點的*型別*是可以編輯的資料，不是寫死在程式碼裡的清單。型別宣告**角色**——
`container`、`task`、`shareable`——而引擎讀的是角色。一個宣告了 `task` 角色的自訂型別
在每個地方都是任務：它會出現在搜尋計數、分析、提醒與 API 裡，不只是看板上。

型別也宣告它的**欄位**：節點資料裡哪些鍵屬於你，各自要用什麼元件顯示。
節點頁上的通用編輯器畫的就是這份宣告。

![節點瀏覽器](/guide/17-node-explorer.png)

節點瀏覽器是最原始的視圖——每個節點、每條關係，對它們的意義不做任何解釋。
