# 整合、Webhook 與 CI/CD

兩個方向：把這裡發生的事告訴別的系統，以及讓別的系統告訴 Shard 那邊發生了什麼。

## 對外：告訴其他系統

![整合](/guide/14-integrations.png)

整合會在有東西變動時往外送一則訊息。兩種：

**Webhook** —— 對你給的網址發一個 HTTP POST。這就是怎麼把訊息送進 Slack、Discord，或任何有 incoming webhook 位址的東西。

**Email** —— 一封 SMTP 信。email 整合也會收到每日摘要和每週摘要。

每一個都要選它在意哪些事件（`task.created`、`task.completed`、`task.overdue`、`project.complete` 等等），以及選填哪一個專案。專案留空就是全部都聽。

### 簽章

每一個對外的 webhook 都用 HMAC-SHA256 簽名，同時放在 `X-Signature` 和 `X-Hub-Signature-256` 兩個標頭裡。收的那一端可以驗證這則訊息真的來自你的 Shard、而且沒有被改過。

### 憑證不會回來

你在這裡輸入的密鑰或權杖會被存起來，然後**永遠不會送回瀏覽器**。讀出來是空的，但它的欄位名還在。

這強制出一條你該知道的規則：**送進去的時候是空的，意思是「維持原樣」**。所以你可以打開一份設定、改一個欄位、存回去，而不會抹掉一個你從來沒看過的憑證。真的要清掉它的話，要明確地設成空值。

## 送達紀錄

![送達紀錄](/guide/23-webhook-logs.png)

每一次嘗試都有紀錄：事件、送到哪裡、對方回的 HTTP 代碼、試了幾次。打開一列可以看到完整的請求和回應。

失敗會照一個越拉越開的排程重試——1 分鐘後、然後 5、30、120、360 分鐘。之後這筆送達會被標記成**已放棄**。

這份紀錄存在的原因是：**webhook 壞掉的樣子就是「沒有聲音」**。當一個 webhook 停止送達某個地方時，你的畫面上不會有任何事情出錯，所以它必須被寫下來，而不是被假設成功。

標頭裡的密碼和權杖在這裡一樣會被遮掉——包括自訂標頭，那些是自由格式的，否則會變成憑證外流的第二條路。

## 對內：CI/CD 回報

打開一個專案（或一個任務），點 **CI/CD**。你會拿到一個專屬的網址。

把你的建置流程指向它。建置完成時它會往那裡 POST，任務就會拿到結果：

- 建置會被記進那個任務的歷史，永遠會——成功或失敗都是。
- 如果回報的狀態對得上某個任務狀態，任務會被更新。
- 如果對不上任何東西，事件還是會被記錄，而任務不會被動。一個認不得的狀態不該默默地變成「完成」。
- 當一個專案裡每個任務都完成時，會發出一個 `project.complete` 事件，你對外的整合會聽到。

**GitHub、GitLab、Jenkins、Drone 和 Bitbucket** 會被自動辨識——它們 payload 的形狀是從請求裡偵測出來的，所以你不用自己轉換任何東西。

回呼必須簽章。沒有簽章的回呼會被拒絕，而不是被接受之後附一個沒人會讀的警告。
