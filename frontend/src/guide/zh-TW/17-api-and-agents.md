# API、API 金鑰與 AI 代理

你在瀏覽器裡做得到的每一件事，程式也做得到。這是程式碼裡用測試強制執行的一條規則：一個只有人用滑鼠點才碰得到的能力，會被當成缺陷，而不是設計。

![API 金鑰](/guide/24-api-keys.png)

## 開一把金鑰

**設定 → API 金鑰 → 新增。** 兩個決定：

**它可以做什麼。** 三種範圍：

| 範圍 | 允許 |
|---|---|
| `read` | 讀 |
| `write` | 讀和改 |
| `admin` | 全部，包含任何會交出憑證的操作 |

**它碰得到什麼。** 金鑰可以不設限，也可以鎖在**單一容器**上——一個專案，或整個身分。鎖在容器上的金鑰碰得到那個容器和它裡面所有東西，其他都碰不到。

金鑰只會在建立的時候顯示**一次**。那時就複製起來。弄丟了就刪掉重開一把。

## 怎麼用

用 `X-API-Key` 標頭對 `/api/v1` 發請求。頁面上有網址和一個可以直接貼到終端機的範例。

完整的端點清單和每一個參數在 `/docs`——那一頁是從程式碼產生的，所以它描述不出一個已經不存在的版本。

## 有哪些東西可用

專案、任務和其他所有節點型別；標籤、衝刺、相依、附件、週期、樣板；搜尋；八份分析報表；工作流程規則；整合和它們的送達紀錄；CI/CD 設定；分享設定；匯入與匯出；備份；以及項目型別註冊表本身。

## MCP：接上一個 AI 代理

如果你用的 AI 助理支援 **MCP**（Model Context Protocol），它可以直接操作 Shard。有大約五十個工具，加上資源和現成的提示詞。

兩種接法：

- **本機**，由助理自己啟動的一個行程。
- **遠端**，在你這台實例的 `/mcp` 位址上，用一個 bearer token 保護。

兩種跑的是同一份程式碼，而且都是拿一把 API 金鑰走 `/api/v1`——所以金鑰的範圍就是代理能做什麼的邊界，沒有第二套權限系統要跟著同步。

## 每個專案自己的代理指示

每個專案的**代理**按鈕給你一段可以貼進助理的文字：這個專案是什麼、它的慣例，以及怎麼連到它。你可以在那裡加上自己的指示，另外伺服器設定裡也有一份全域的，套用到所有東西。
