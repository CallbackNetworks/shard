# ADR-0067: 快速切換不需要永久佔著畫面

## Status
Accepted

## Date
2026-08-07

## Context

ADR-0066 把身分與自訂容器型別移出 rail 之後，剩下的問題是專案：使用者要能快速
在專案之間切換，但**不希望這件事佔用 sidebar**。

命令面板（⌘K）其實早就會列專案了，所以問題不是「有沒有」，而是「夠不夠快」。
用開發資料庫（18 個專案）檢視，實際的弱點有三個：

1. **順序是任意的**。沒有查詢字串時，面板取 `projects.filter(active).slice(0, 8)`
   —— API 回傳順序的前 8 個。你常切換的那兩三個專案不一定在裡面，必須先打字。
   對一個切換器來說，順序就是它全部的價值。
2. **它不理會身分聚焦**。`IdentityFocusContext` 已經有 `filterProjects`，
   Dashboard 用了，面板沒用。聚焦在某個身分時，面板仍然列出所有專案，
   甚至能透過 search API 帶出聚焦範圍外的專案。
3. **沒有專屬入口**。⌘K 是「搜尋或跳轉」的通用入口，開啟後專案跟導航指令、
   任務、節點混在一起。

## Decision

**專案切換屬於命令面板，不屬於 rail。把面板變成一個真正的切換器，而不是在
sidebar 上再開一塊常駐空間。**

1. **記住你最近去過哪裡**（`utils/recentProjects.js`）。一個 localStorage 上的
   小型 store，只存**專案 id**，最多 8 個。名稱、狀態、任務數都已經在
   `['projects']` query 裡，複製一份只會在改名時變成錯的。`touchProject()`
   在 `ProjectDetail` 載入成功時呼叫——以載入到的專案為準，不是路由參數，
   所以壞掉的 id 不會進入切換器。

2. **面板有兩種模式**。`mode='all'` 是原本的通用命令列；`mode='projects'`
   是專屬切換器：只有專案，因此最近使用的順序不會被導航指令、任務與節點稀釋。
   `g` `p` 和弦開啟切換器模式，沿用既有的 `g h`/`g a`/`g i`/`g g` 詞彙。

3. **alt-tab 語意**。切換器不列出你當前所在的專案。Enter 落在你已經在的地方，
   會讓最快的路徑變成沒有動作；排除它之後，`g p` `Enter` 永遠是「回到上一個
   專案」。通用模式仍然列出當前專案，因為那裡不是切換器。

4. **面板服從身分聚焦**。`filterProjects` 套用在專案來源上，search API 回來的
   專案也必須落在同一個可見集合內才會出現——否則聚焦在 rail 上生效、在面板上
   失效，等於沒有聚焦。

沒有採用 `⌘P`：那是瀏覽器的列印鍵，劫持它會弄壞列印。

## Consequences

**正面**

- `g` `p` `Enter` 兩鍵加一個 Enter 回到上一個專案，且 **rail 上完全沒有增加任何
  一列**——ADR-0066 建立的不變式保持成立。
- 專案數量再多也不影響：最近使用的排前面，其餘可搜尋。18 個專案時，你關心的
  兩個永遠在最上面。
- 身分聚焦現在在面板與其他頁面說同一套話。
- 封存的專案不再出現在切換器裡，除非你剛去過或打出它的名字。

**負面 / 取捨**

- 最近清單存在 localStorage，**不跨裝置同步**。這是刻意的：它記錄的是「這台
  機器上的這個工作階段你在做什麼」，同步過去只會互相覆蓋。若日後要同步，
  `user-preferences` 這條路已經存在。
- 只追蹤 `/projects/:id`。容器（`/c/:id`）與節點頁面不進入最近清單。
- 面板的區段標題原本是寫死的英文，這次一併改為翻譯字串——否則中文介面會出現
  一半翻譯一半沒翻的清單。
