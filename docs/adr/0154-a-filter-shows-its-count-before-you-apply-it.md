# ADR-0154: 一個篩選要在被套用之前就說出自己有幾筆

## Status
Accepted

## Date
2026-09-05

## Context

ADR-0153 出去之後，使用者的問題是：「孤立的真的有必要單獨通過選項顯示嗎？」

這是兩個問題疊在一起，而答案不一樣。

### 那個問題有必要，而且新加的欄位蓋不掉它

ADR-0153 給每一列加上了邊數，0 標紅。直覺上「孤立」看起來就變成多餘的了——沒接東西的自己會標紅。實測不是這樣：

| | 筆數 |
|---|---|
| 孤立節點 | 32 |
| 其中 0 條邊 | 11 |
| 其中**恰好 1 條邊** | 21 |
| 整個資料庫裡 0 條邊的節點 | 11（**全部都是孤立的**） |

也就是 `0 條邊 ⊊ 孤立`（11 ⊂ 32），紅色的 0 是**嚴格子集**，不是更大的網。那 21 筆是 `ChungChen/*` 專案，每一筆都有一條 `owns`（有人擁有它），沒有任何 containment（沒人歸檔它）。**在邊數那一欄，它們跟健康的節點長得一模一樣。**

而且它們是比較值得找的那一半：什麼都沒接的東西一眼就是垃圾；有人擁有、卻掉出階層的專案是真的工作。

**順帶更正 ADR-0153 的一句話。** 那份文件（以及 CLAUDE.md、guide 兩個語言版、一段 CSS 註解）寫著「0 標紅……它抓得比 `loose` 多」。**寫反了，而且是在量之前寫的。** 歷史 ADR 不改，所以更正記在這裡；其餘四處已經照量到的方向改掉。這正是為什麼「把數字印出來」本身就是稽核工具——ADR-0153 是先加了邊數欄位，才看見 loose 的定義漏了 `owns` 那條軸；同一個欄位這次否證的是我對它自己的描述。

### 那個排場沒有必要

`?loose=1` 當時佔的是：一個 `SHAPE` 區塊標題、一個獨立樣式的勾選框、以及三行說明段落，約 90px。而它正上方的狀態篩選做的是同一件事（把集合縮小），形式卻完全不同——狀態是「一列 + 一個數字」。

更糟的是**它沒有數字**。所以要知道有沒有東西是孤立的，唯一的辦法是勾下去看。**在一個「專門用來找出你不知道存在的東西」的篩選上。**

## Decision

**一、留下這個問題，取消它的專區。** `SHAPE` 標題與說明段落移除，`loose` 變成篩選清單裡的一列，跟狀態列同一個 `facetRow` 形狀，排在最前面。說明搬到那一列的 `title` tooltip，長版留在 guide。它拿的是一個菱形字符而不是狀態色——顏色家族有它自己的意思（ADR-0088），而孤立是形狀不是狀態。

**二、`facets` 多回一個 `loose` 計數。** 規則跟狀態 facet 一樣，而且現在明確寫成通則：**每一個計數關掉自己那個篩選、套用其他所有篩選**，因為篩選旁邊的數字必須是「切換到它之後你會拿到的集合大小」；套用了自己，它就塌成已經選中的那一個，旁邊也就沒有東西可以切換了。`listing_query` 為此多一個 `apply_unfiled` 旗標，跟既有的 `apply_status` 對稱。

實測行為：

```
（無篩選）              total 334   loose 32
?type=project           total  66   loose 22
?type=project&status=archived
                        total   8   loose  0     ← loose 仍受其他篩選約束
?unfiled=1              total  32   loose 32     ← loose 不受自己約束
```

**三、`STATUS` 標題改成 `Filter`／「篩選」。** 一份清單，一種語法：任何縮小集合的方式都是「一列 + 一個數字」。混在同一個標題底下的代價是狀態值失去了「Status」這個標籤，但 todo / done / failed 本來就自我說明，而菱形字符與置頂位置把孤立跟它們分得開。

## Consequences

- 打開 Data 頁就看得到有幾筆孤立，不必先勾再看。這是這次改動真正買到的東西。
- 篩選欄少了一個區塊標題和三行說明，短了約 90px；`nodeExplorer.filterShape` 與 `filterStatus` 兩個 i18n key 退場，`looseOnly` 的字面從「只看散落的」改成「孤立」（它不再是一個「只看……」的勾選框，而是一列）。
- 每頁的 facets 請求多做一次 COUNT。跟它省下的那一次「勾下去看看有沒有東西」比，划算。
- ADR-0153 有一句關於「紅色 0 抓得比 loose 多」的話是錯的，更正在本文件的 Context 裡；程式碼與文件的其餘四處已改。**歷史 ADR 不編輯**——一份會被改寫的決策記錄不是記錄。
- Guide 第 16 章與 `17-node-explorer.png` 同步更新。
