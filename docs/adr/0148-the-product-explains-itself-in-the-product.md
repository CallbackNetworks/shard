# ADR-0148: 產品要在產品裡把自己說清楚

## Status
Accepted

## Date
2026-09-04

## Context

這個產品沒有任何「它自己怎麼用」的說明，而且是三種不同層次的沒有。

**第一，app 裡沒有教學。** 唯一接近的東西是 `GettingStarted`：四張純文字卡片，
只在「一個專案都沒有」時出現。也就是說它介紹了六件值得知道的事裡的第一件，
然後在你做完那件事的瞬間永遠消失。真正讓這個產品和一個清單 app 不同的東西——
到期日驅動的提醒、`contains` 與 `owns` 兩條軸、決策紀錄、規則引擎、agent 的 API 面——
沒有任何東西介紹過。

**第二，repo 裡的圖文導覽進不了 app。** `docs/screenshots.md` 有 25 張截圖與說明，
但 `frontend/Dockerfile.prod` 的 build context 是 `./frontend`——**`docs/` 底下的檔案
在建置時根本不存在**。所以那份導覽只有翻原始碼的人讀得到，用這個 app 的人一張都看不到。

**第三，那些圖已經過期了。** 它們是 2026-08-30 手動拍的，之後 ADR-0133（hover 動畫吃掉入場
動畫）與 ADR-0134（明確 grid track 塞不進螢幕）都改過版面。一份會過期而沒有人寫下到期日的
文件，比沒有文件更糟：它看起來還是權威的。

三件事有同一個根：**說明是手工做的一次性產物，而不是從跑起來的產品產生的東西。**

## Decision

**產品在產品裡把自己說清楚，而且說明的圖片是產生出來的。**

四個部分：

**1. 截圖從跑起來的 app 拍，一次寫兩個目的地。** `e2e/tests/guide-shots.spec.ts` 是所有
教學圖片的來源，`scripts/screenshots.sh` 負責種資料、跑它、報告改了什麼。它同時寫入
`frontend/public/guide/`（app 自己的副本，包在 SPA build 裡）與 `docs/screenshots/`
（repo 的副本）。兩份不能合成一份，理由就是上面那條 build context。

這支 spec **不是 CI 檢查**：它會寫進工作目錄，而且需要有資料才拍得出值得看的東西，
所以 `playwright.config.ts` 預設把它排除，由 `GUIDE_SHOTS` 打開。它留在同一個 testDir 而
不是搬去別的地方，是為了繼承其他 spec 用痛學到的 `open()` 就緒規則——`networkidle` 不夠：
外殼會 render 而路由頁不會，這時拍到的是一張永遠不會失敗的空欄位照片。

三個實跑才發現的問題各自留了註解：容器以 root 跑而目的地是 bind mount，所以每張 PNG 都是
root 所有（ADR-0138/0139 的同一類擁有者陷阱的縮小版，解法是把呼叫者的 uid 傳進去、寫完就
交出去）；`deviceScaleFactor: 2` 每張 2.5MB、一共 60MB 的截圖進 image，而在說明欄位裡是縮到
一半畫的，2x 買不到任何看得見的東西；suite 預設的 30s timeout 是給單一斷言用的，
把最後一批截圖攔腰砍斷，看起來像頁面壞了、其實是碼錶。

**2. `/guide` 是圖文說明頁，內容是 markdown。** 章節放在 `frontend/src/guide/{en,zh-TW}/`，
用 `import.meta.glob` eager 載入——`import` 而不是 `fetch`，所以一個不存在的章節是 build error
而不是有人點下去那一刻的 404。章節在 URL 裡，因為說明是拿來互相丟連結的東西，
「去看決策那一節」必須是一條連結而不是一段指路。缺少翻譯時退回英文：
「說明在你的語言下是空白」比「說明是英文」更糟。

同一批改動補上 `@tiptap/extension-image`。`MarkdownPreview` 是這個 app 唯一的 markdown
renderer，而 StarterKit 沒有 image node——`![alt](src)` 一直被畫成它自己 markdown 的字面文字，
不只在說明頁，任何一則帶截圖的任務描述都是這樣。`html: false` 維持不變，所以接受的是
markdown 寫法而不是貼進描述欄的 `<img>`。

**3. 導覽是宣告出來的步驟，不是第二份 app。** 一個步驟指名一條路由和一個 `data-tour`
選擇器，從不指名一個元件——這是「一段導覽」和「這個 app 的第二份實作」之間的差別：
加一個步驟是改資料。

遮罩是**目標周圍的四片 div**，不是 SVG mask 也不是一個巨大的 `box-shadow`：中間那個洞完全
不接收 pointer event，所以正在被解說的控制項在那一步裡仍然按得下去。整層 overlay 透過
portal 掛到 `document.body`，而這是承重的而不是整潔——入場動畫留下的 `fill-mode: both`
transform 會讓祖先變成 `position: fixed` 的 containing block（ADR-0122 用 popover 撞過、
ADR-0129 用 modal 撞過，一層全螢幕遮罩是同一機制裡最明顯、也最難從程式碼看出來的版本）。

自動開始有三道守門，每一道都對應一個**實際看到**的缺陷，不是想像出來的：`isLoading`
（沒存過的偏好和還沒抓到的偏好都是 falsy，少了它會對回訪者閃一下再消失，比兩種行為都糟）；
**路由**（第一步住在 `/`，而 overlay 會導航到步驟的路由，所以第一次來就打開 `/guide` 的人
會被直接抓走——要說明書卻被塞了一段導覽，正是那種讓人去關掉它的「貼心」）；`index`
（讓「略過」不會馬上被復原）。

**4. 入門清單是從活資料推導的，不是存起來的。** 存起來的清單在有人繞過那個流程建立或刪除
東西時就會漂移，而且是**往上**漂——它會為已經不存在的工作恭喜你。代價是「用這個函式不認得
的方式做完某一步」不會被打勾，而那是比較正確的錯誤方向。完成即是自己的關閉：
一個寫著「6 / 6」的面板就是在請求被關掉，而請人去關掉一句恭喜是一種小小的無禮。

## Consequences

- app 內有一份圖文說明（`/guide`），側欄有固定入口（locked，和 Overview、Settings 同級——
  會去找說明的人，正好就是那個把看不懂的列都藏起來的人），`?` 說明視窗也有入口。
- 教學圖片可以一道指令重生，所以它們不會比產生它們的那一次執行更舊。
- `docs/screenshots.md` 改寫成指向新的一組圖，並且說明它們是產生的。舊的 25 張手拍圖被刪除。
- 新使用者第一次進 Overview 會看到七步導覽，之後可以從說明頁或 `?` 視窗重播。
  「看過」存在伺服器偏好而不是 localStorage：同一個帳號換一台機器不該再被走一次。
- `GettingStarted` 與它的九個字串被刪除。
- `MarkdownPreview` 現在會畫圖片，這也影響任務描述與助理回覆——是想要的，
  但它是一個超出說明頁範圍的行為改變。
- `tourSteps.test.js` 斷言每個步驟的 anchor 真的被某個元件畫出來。overlay 對找不到的 anchor
  會跳過該步驟，那是正確的執行期行為、也是很糟的失敗訊號：被不相干的重構刪掉的步驟，
  看起來和被使用者自己的 widget 設定藏起來的步驟一模一樣。
  這個守門測試**排除 `components/tour/` 自己**，而那個排除就是這個測試的全部意義——
  `tourSteps.js` 本身含有它宣告的每一個選擇器，掃它等於拿宣告去比對自己，
  第一版在真的弄壞一個 anchor 之後仍然全綠（ADR-0061 的同一個陷阱，用負向控制抓出來的）。
- 截圖 spec 不在 CI 裡跑。這是刻意的取捨：它需要有資料的資料庫，而在 CI 那個乾淨的資料庫上
  它只會產生一批空畫面的照片——也就是一個回報成功、卻讓文件變得更糟的工作。
  代價是「圖過期了」不會自動被發現，那仍然是人的責任。
