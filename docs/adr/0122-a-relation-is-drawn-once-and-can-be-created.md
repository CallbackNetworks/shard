# ADR-0122: 一條關係只畫一次，而且建得出來

## Status
Accepted

## Date
2026-08-29

## Context

ADR-0118 把決策升成節點型別，給了它 `supersedes` 和 `governs` 兩條關係。使用者回來說：決策頁還是看不太出決策鏈，也看不出這個決策跟其他節點發生了什麼關係；而且卡片上除了「採納」和「拒絕」之外沒有別的按鈕。

兩句話，三個各自獨立的成因。

### 一、`governs` 從來沒有人建得出來

`api/client.js` 從 ADR-0118 那天起就有 `linkDecisionToWork`、`unlinkDecisionFromWork`、`getDecisionsGoverning` 三個函式，**全 codebase 零呼叫端**。伺服器端是完整的：`POST /nodes/{id}/edges` 收 `governs`，`GET /nodes/{id}/decisions` 是反向讀。缺的只有畫面。

後果不是「少一個功能」，而是這條關係的意義整個落空：決策卡片讀得出自己管到哪些工作，而那件工作打死說不出自己是被誰決定的——**看著任務的人，正是不知道它為何存在的那個人**。同類前例是 ADR-0083（`c`/`n`、`removeLabelFromTask` 都造好了卻沒接上）。

正式站的數字說明了代價：103 筆決策，`supersedes` 邊 1 條、`governs` 邊 1 條，都是當初測試留下的。

### 二、七個控制項裡只有兩個看得出是控制項

決策卡片有七個動作：採納、拒絕、取代、開節點、匯出、編輯、刪除。前兩個有文字、有外框；後五個是 13px 的 `--kt-faint` 圖示，無框、無底、無字。**五個並排的圖示不會被讀成五個動作，會被讀成裝飾**，所以卡片看起來就只有兩顆按鈕。

而且狀態控制只在 `proposed` 出現：

- 一筆已採納的決策**沒有任何狀態按鈕**——想標成棄用，沒有路。
- 一筆被拒絕的決策也沒有——想重新提案，沒有路。

也就是說，一筆決策的狀態實際上只寫得了一次，然後就被自己的結果凍住。

### 三、同一條邊被講了三遍，鏈卻還是看不出來

一條 `supersedes` 在演進鏈裡同時以三種形式出現：縮排、`被上方的決策取代` 那行字、以及兩張卡片上各自的 chip（「取代 X」和「被 Y 取代」）。而那兩個 chip **同一個圖示、同一個灰**，方向只活在句子裡。三次陳述，沒有一次是一條線。

更關鍵的是欄位本身在說謊：`LINEAGE` 這一欄列的是「所有非待審決策」，正式站有 102 筆是長度為 1 的「鏈」。**一份清單掛著 Graph 的名字，唯一一條真的鏈就藏在裡面看不見。**

（順手抓到的：`decision.source` 是自由字串，正式站有 `assistant` 和 `frontend` 兩個值，卡片上直接印出 `decisions.source.assistant` 這個 key。）

## Decision

三件事，一條原則：**一條關係只畫一次，而且畫它的地方就要建得出它。**

**`governs` 兩端都接上。** 卡片新增「管轄工作…」按鈕，開一個 picker（`GovernPicker`），依 **role** 過濾候選節點（`task` 或 `container`，ADR-0090：帶 `task` role 的自訂型別在每個地方都算任務），寫入走通用邊介面。既有的 governs chip 加上解除鈕。反向那面是 `GoverningDecisions` 這一條帶子，掛在 `/n/{id}` 與任務列的 `MembershipPanel` 上，帶著決策狀態一起顯示——一件工作跑在已被取代的決策上，是這裡唯一值得一眼看出來的事。同時 `governs` 加入 `MembershipPanel` 的 `CORE_RELS`，否則同一條邊會被畫兩次。

**動作分主次。** 狀態改變依現況給按鈕，每個都有字：

| 現況 | 提供 |
|------|------|
| `proposed` | 採納、拒絕 |
| `accepted` | 棄用 |
| `deprecated` | 重新提案 |
| `superseded` | 無 |

`superseded` 刻意沒有按鈕：那個狀態是 `supersedes` 邊的後果（ADR-0118），一顆能改它的按鈕會讓狀態跟邊互相打臉。要解除，就去解除那條邊。

兩個關係寫入（取代、管轄）用帶字的次級按鈕，其餘四個收進一顆 `⋯`（`OverflowMenu`，portal 到 body）。

**鏈只講一次，講在軌道上。** 鏈內的卡片不再重複 rail 已經說過的 chip（`chainIds`，同 ADR-0069/0094「在可見集合內解析」的規則）；rail 本身就是那條邊，所以撤銷取代的控制項移到 rail 上。鏈外的 chip 用箭頭方向 + 實線／虛線區分，不引入新的色系（ADR-0088）。`LINEAGE` 只放真的鏈（`chain.length > 1`），單筆記錄移到 `STANDALONE`，兩邊各自報自己的數量。

## Consequences

- 一個決策記錄現在可以在頁面上被連到工作，工作那邊也說得出自己被誰決定——ADR-0118 的兩條關係到此才是雙向可用的。
- 一筆決策的狀態可以來回改，`superseded` 除外。**這是刻意的不對稱**，代價是「把一筆已取代的決策直接標成棄用」做不到，得先撤銷取代關係。
- `LINEAGE` 的數字從「有結果的決策數」變成「鏈的數量」，正式站會從 102 掉到 1。這個數字變小是重點，不是退步。
- `OverflowMenu` 是新的共用原語。它 portal 到 `document.body`：決策欄是 `overflow: hidden`，而卡片的進場動畫留下 `transform`，會讓自己變成 `position: fixed` 的 containing block——兩者都會讓就地彈出的選單跑掉。這兩個都是截圖才看得出來的，測試全綠（第三次踩到同一類，見 ADR-0114、ADR-0118）。
- 決策的 `source` 找不到翻譯時退回顯示原字串，不再印出 i18n key。
- 後端一行沒動。這整件事從頭到尾都在前端，而缺的東西在 ADR-0118 當天就已經全部寫好了。
