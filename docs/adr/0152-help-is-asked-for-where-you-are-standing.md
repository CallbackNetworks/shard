# ADR-0152: 求助是站在某個地方問的

## Status
Accepted

## Date
2026-09-04

## Context

ADR-0148 讓產品在產品裡說明自己：一個圖文說明頁，加上一個首次造訪的聚光燈導覽。

那個導覽有**七步，全部在 `/` 上**。App 有十八個畫面，其中十七個什麼都沒有。

這個形狀是錯的，而且錯得很典型：導覽走的是「產品想先講什麼」，而人是**站在某一頁上、對著那一頁**開始困惑的。一個只介紹大門的導覽是簡介，不是求助管道——因為求助是一個具體的、有位置的動作。實際的症狀是：`/graph-types` 上那三個角色 checkbox、`/explorer` 的「只看散落的」、規則頁那兩個計數（跑了 47 次、生效 0 次）——這些是產品裡最需要一句話的控制項，而它們全部沒有任何一句話。

說明頁那半也一樣不夠。五章，寫得抽象（「Shard is a graph」是第一章第一句），而且**只涵蓋大約一半的模組**：目標、樣板、衝刺、送達紀錄、API 金鑰、分享、離線、快捷鍵——一個都沒寫。使用者的原話是「不要用太抽象的話，請盡量讓沒有基礎的人也能明白」。

還有一筆欠著的帳。ADR-0151 記錄了導覽的 scrim 攔截 pointer events，害整合測試每一個 `locator.click()` 都超時，並且**明說真正的修法沒有做**：

> 導覽仍然是一個全頁的點擊黑洞。要讓「首次造訪」重新可測，導覽得先不是這種東西。

十七個新導覽會把那個缺陷從一頁擴大到十八頁。所以它必須先修掉。

## Decision

### 一、導覽變成 per-page，而且**不會自己跳出來**

`tours.js` 是一份註冊表：十八個導覽，六十二步，每一個宣告 `route`（或 `match`，給帶 id 的路由）和一串 `{ id, anchor, placement }`。

只有 `overview` 帶 `auto`。**其他十七個都要人開口問。** 每進一個新畫面就開始解釋自己的產品不是在教學，是在打斷，而且打斷的時機正好是有人終於開始跑起來的時候。

文案的 key 是**推導出來的**（`stepKeys()`），不是宣告的。在 `id: 'rail'` 旁邊再寫一次 `titleKey: 'tour.overview.rail.title'` 是把同一件事講三遍，而它們不一致時的症狀是氣泡裡出現一個 i18n key。

### 二、開口問的地方是每一頁左下角一顆按鈕

`PageTourLauncher` 掛在 layout 上**一次**，問註冊表「現在這條路徑有導覽嗎」再決定畫不畫。替代方案是在十八個頁面標頭各加一顆——而那些標頭不是同一個元件（`.kt-page-header`、專案頁、助理頁各一套），所以那是十八次編輯和十八個漂移的機會。

上面那顆點是它會被發現的唯一原因。它在你走過那一頁的導覽之後就永遠消失，所以它是一個關於**你**的事實，不是一個常駐裝飾。

`?` 也改成開「你現在這一頁」的導覽而不是永遠開大門那一個。說明頁的側欄則列出全部十八個並打勾——那是唯一看得見整套的地方，第一天可以當檢查清單。

### 三、scrim 不再攔截 pointer events（ADR-0151 欠的那一筆）

`.scrim` 改成 `pointer-events: none`，`aria-modal` 拿掉。導覽現在**只是把頁面調暗**：底下的 app 全程可用，被解釋的那個控制項可以當場按下去試。

隨之而來的兩個行為，是「可以按到別的地方」之後才成立的問題：
- 路由導航**每個導覽只做一次**（`routedFor`）。原本每次 `location.pathname` 不等於 step route 就導航，使用者一點別的地方就會被拽回來。
- **離開那一頁就結束導覽。** 一個「這一頁的導覽」在你不在這一頁時就結束了；繼續下去只會把聚光燈打在剛好落在那個座標上的隨便什麼東西上。

### 四、說明頁重寫成一模組一章

五章變十八章，兩種語言。每一章都有截圖，寫法是「這個畫面是做什麼的、點下去會發生什麼、接下來做什麼」。第一章是〈開始使用〉：三個觀念、五分鐘的第一個循環（建專案 → 加任務 → 拖一張卡 → 回總覽看數字動了）。

截圖從 18 張加到 27 張——原本有七章在描述讀者從沒被展示過的畫面。編號是**拍攝順序，不是閱讀順序**：`README.md` 和 `docs/screenshots.md` 用檔名引用它們，為了讓一頁裡的圖片換位置而重新命名十八個檔案並弄壞兩份文件，不划算。

### 五、守門測試補上「反方向」

原本的 `tourSteps.test.js` 排除整個 `components/tour/` 目錄，理由是對的（`tours.js` 自己就含有每一個 selector，掃它等於拿宣告跟自己比）。但**排除目錄而不是排除檔案**，讓 launcher 自己那個 anchor 永遠驗證不到——刪掉它，守門會說沒事。現在只排除 `tours.js` 一個檔案。

再加一條新的：**rail 上每一個目的地都要有導覽**。這是同一個缺陷從另一個方向來——加一個模組進 rail、沒有人指向它，而「少了一個導覽」完全沒有症狀：那一頁的按鈕就是不出現，沒有測試、截圖或型別錯誤會提到它。

## Consequences

- 十八個畫面各有導覽（62 步 × 2 語言 = 248 條文案），說明頁 18 章 × 2 語言 ≈ 8,100 字。
- **ADR-0151 的租金付掉了。** 導覽不再擋住它底下的 app，所以那份 ADR 裡「首次造訪不可測」的理由消失了一半——`e2e/global-setup.ts` 那個偏好保留著（它仍然是回訪使用者的真實狀態，也仍然避免氣泡蓋在某個測試要點的控制項上），但它不再是**唯一**讓其他二十個測試能跑的東西。
- 每一頁多一顆浮動按鈕。它讀 `--rail-w`（ADR-0088 的規則），並且在窄螢幕上丟掉文字只留羅盤。
- 寫這一輪的過程中，用實際程式碼核對說明文字抓到四處我自己寫錯的事實：關鍵路徑**不在**分析頁上（只有 API 有）、`g→i` 去的是身分不是整合、`N` 建的是專案不是「當前情境的項目」、WIP 上限在 UI 上是唯讀的而且變的是琥珀色不是紅色。**照著程式碼寫文件，會找出文件裡的錯；照著記憶寫，只會把記憶抄下來。**
- 沒有做的事：導覽步驟不會等使用者真的按下被聚光的那顆按鈕才前進。它仍然是「看」而不是「做」。要做成後者，每一步得宣告一個完成條件，而那是另一個決策。
