# ADR-0114: 關係要說得出自己兩端是誰

## Status
Accepted

## Date
2026-08-27

## Context

Node Explorer 是整個產品裡唯一一頁「主題就是關係本身」的畫面，而它把每一條邊畫成
`contains → 4f3a…`。另一端的節點叫什麼名字，它一個字都沒說。

這不是缺資料。`EdgeOut` 從一開始就內嵌了 `source` / `target` 兩個 `NodeRef`（id、type、
title、status），schema 上那一行的註解甚至直接寫著 "embedded to spare clients an N+1"，
`GET /api/nodes/{id}/edges` 也用 `selectinload` 把兩端一起撈出來。`NodePage.jsx` 用的就是
這兩個欄位。只有 `NodeExplorer.jsx` 那一列印了原始 id —— 伺服器把名字送到了，客戶端沒撿。

同一個班次往外看，「資料」那一組頁面有同一個症狀的不同版本：

- **每個清單都是平的。** `/t/{type}`（型別清單）、Node Explorer 左欄、未歸檔頁，每一列
  只有標題。ADR-0094 已經做出 `AncestryTrail`（一個節點住在哪裡）並掛在專案頁、容器頁、
  節點頁上，但那個元件是**自己抓自己那一筆**的；清單頁要用它，就得一列一個請求，也就是
  那個 endpoint 一開始就設計成批次的原因。所以清單頁一頁都沒有掛。
- **關係的型別宣告完全看不到。** ADR-0078 讓每個 relation 宣告
  `allowed_source` / `allowed_target`，註冊表也把它們服務出去了，但 `/graph-types` 只列出
  關係的名字。哪一種節點可以接在哪一端，唯一的發現方式是「送一個邊出去、讀被拒絕的錯誤
  訊息」。那個訊息寫得很好（ADR-0078 特意讓它指名該用哪個關係），但它是**失敗**才看得到的
  文件。
- **未歸檔頁的前提就是「沒有東西容納它」**，所以在那裡放麵包屑永遠是空的。那頁真正回答不了
  的問題是「這個東西到底有沒有連上圖」。

一個清單頁看不出關係，跟一條邊看不出兩端是誰，是同一件事的兩個尺度：資料在那裡，畫面沒讀。

## Decision

**一條邊要說得出兩端是誰，一個清單要說得出每一列住在哪裡。**

1. **Node Explorer 的關係列改讀 `EdgeOut.source` / `target`** —— 型別標籤 + 標題，點下去
   把選取移過去。原始 id 只在伺服器沒給 `NodeRef` 時當退路。

2. **`useAncestry(ids, scope)`** 是 ADR-0094 那個批次 endpoint 的客戶端另一半：一頁把它
   要畫的所有 id 一次送出去，拿一份 map 回來，再把各自那一筆交給每一列。`AncestryTrail`
   多收一個 `entry` prop，有值就不自己發查詢 —— 單一節點的頁面照舊自己抓，清單頁走批次。
   掛在 `/t/{type}` 與 Node Explorer 左欄。

3. **`buildEgoNetwork` + `EgoNetwork`**：以選取的節點為中心，往外走兩跳的鄰域圖，點鄰居就
   換中心。它吃的是頁面已經有的 `/graph/map` 切片，所以第二跳不需要一個鄰居一個請求。
   兩跳是關鍵：一跳就是清單換個畫法，兩跳才看得出形狀。版面計算是純函式，因此不需要 DOM
   就能測。這裡刻意不重用 `/structure` 的畫布 —— 那一套是為 containment 骨架建的
   （ADR-0069），問的是「整個產品長什麼樣」，不是「這個東西接了什麼」。

4. **`/graph-types` 把每個關係的端點宣告畫出來**：`來源 → 目標`，型別解析成標籤、角色寫成
   「任何具備 X 角色者」、`NULL` 寫成「任何節點」。`contains` 不是用 allow-list 綁的，是被
   containment 規則綁的，所以它印的是那條規則本身，而不是一句會說謊的「任何 → 任何」。

5. **未歸檔頁改列每一列實際擁有的關係與數量**（`Depends on 2`、`Labeled 3`），沒有就明說
   「完全沒有關係」。那一頁的問題本來就不是「住在哪」，是「有沒有連上」。

Node Explorer 的選取改成向伺服器讀（`GET /nodes/{id}`），不再從當前型別那一頁結果裡找 ——
鄰域圖會把中心換到別的型別的節點上，用清單去找會每跳都掉一次。

## Consequences

- 關係在畫面上有名字了，Node Explorer 才真的能用來檢查圖。同一份 `NodeRef` 現在被
  `NodePage` 跟 `NodeExplorer` 讀，沒有第二套解析。
- 清單頁的階層一次查完。多一個請求（每頁一次），換掉「每列一次」跟「乾脆不問」。
  伺服器在 200 個 id 切斷，客戶端也跟著切，所以被丟掉的是這一頁自己選的尾巴。
- ADR-0078 的端點宣告從「錯了才看得到」變成「事前看得到」。代價是這頁多一行需要跟著
  註冊表走的描述；`contains` 的那一行是寫死的散文，因為它的規則本來就不是 allow-list。
- 鄰域圖多讀一次 `/graph/map`（切換到圖形檢視時才發），上限 2000 個節點。超過鄰居上限時
  它會說自己是局部的，而不是讓一張被砍掉的圖看起來像完整的。
- `AncestryTrail` 現在有兩種餵法。這是刻意的：批次是清單的需求，不是所有呼叫端的需求，
  硬要所有頁面都先組 id 清單反而會讓單一節點的頁面變複雜。
