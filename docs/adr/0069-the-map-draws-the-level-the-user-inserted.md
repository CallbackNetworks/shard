# ADR-0069: 結構圖畫出使用者插進去的那一層

## Status
Accepted

## Date
2026-08-07

## Context

ADR-0065 讓每個容器的數字算到整棵子樹，ADR-0068 讓所有回報面對這個數字有同一個答案。剩下的是**看**：結構圖有四種版面，只有 network 會把「盒子裡的盒子」畫成一條連線，另外三種都把層級寫死成 identity → project → task：

- `tree.js`：一個 identity 底下是一整排 project，project 底下是一排任務。三層，寫死。
- `mindmap.js`（sankey）：三個欄位 identity｜project｜task，每個容器一列，順序就是 `visibleProjects` 的順序。
- `territoryModel.js` + `TerritoryCanvas`：每個 identity 一塊領地，領地裡是一排卡片。

所以使用者把三個專案收進一個新的 `area` 容器之後，那個 area 會**和它所包含的專案並排**畫在同一排，看起來像它們的兄弟。圖上唯一還算誠實的是 network，而 network 是四種裡最難讀的一種。

更糟的是卡片上的數字：`graphStructure.js` 從圖的切片自行推導 enrichment（ADR-0037 的設計），而它算的是**直接子任務**。所以同一個容器，專案頁說 8，結構圖的卡片說 6。ADR-0068 才剛把伺服器端的答案統一，客戶端這份自己算的又分岔了。

## Decision

**四種版面問同一個模組要層級，各自決定怎麼畫。**

1. 新增 `utils/containerTree.js`：`buildContainerForest(containers)` 回傳 `roots / childrenOf / depthOf / parentOf`，`flattenContainerForest` 給欄位式版面用的深度優先順序。四種版面共用它，所以它們**不可能對圖的形狀有不同意見**，只會對怎麼畫有不同意見。

2. 父子關係在**可見集合內**解析。搜尋、風險篩選、身分聚焦都會讓父節點消失，這時子節點必須升級成根節點被畫出來，而不是跟著父節點一起不見。同理，資料若描述出一個環（後端擋得住，但切片可能不完整），每個容器仍然只畫一次——渲染器不該被資料掛住。

3. 各版面的畫法：
   - **tree**：遞迴的整齊樹。子容器和任務共用父容器下面那一排，寬度由下而上累加，所以插一層是把它持有的工作往下推一排，不是擺到旁邊。從父容器連過去的是 `contains` 線，不是 identity 的 ownership 線。
   - **sankey**：列的順序改成深度優先，每深一層在 project 欄裡縮排（欄寬相應變窄），父子之間補一條 `contains` 流線。
   - **territory**：只有**根**容器佔領地裡的一格，子容器畫在父卡片**裡面**——「在裡面」正是使用者插這一層的意思。連帶地，選取一個容器會點亮它的整條祖先鏈與整個子樹，否則畫在暗掉的父卡片裡的亮子卡片會自相矛盾。

4. 地圖自己推導的數字改用 ADR-0068 的規則（整棵子樹的 top-level 任務），並新增 `directTaskCount`，卡片因此可以標「(8 在子容器裡)」。**客戶端自行推導不代表可以推導出不同的答案**。

## Consequences

正面：

- 插進去的那一層在四種版面裡都看得見，而且看得出是「上下」而不是「並排」。
- 卡片上的數字和專案頁、分享連結、API 一致。
- 之後要加第五種版面，層級這件事已經有一個現成的、測過的模組。

代價與限制：

- `tree` 版面的畫布會隨巢狀深度變高，深樹在「fit」縮放下會變得很小——縮放和平移已經有，但**沒有為深樹做任何自動聚焦**。
- 篩選掉父節點時子節點升級成根，這是刻意的（東西不會消失），但畫面上會看不出它其實有一個被藏起來的父容器。
- `territory` 的巢狀卡片沒有各自的展開狀態上限；一棵很深的樹會讓單一領地的卡片變得很長。
- 這一輪沒有做的仍然是那件事：**沒有「在這裡插入一層」的動作**，插層還是要到 `/n/{id}` 手動接拆邊。
