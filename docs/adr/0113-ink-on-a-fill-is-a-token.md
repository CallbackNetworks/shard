# ADR-0113: 填色上的墨色是一個 token，不是寫死的黑或白

## Status
Accepted

## Date
2026-08-27

## Context

ADR-0088 把顏色收斂成三個家族，並且要求每個家族在 `:root` 和 `[data-theme="light"]`
兩邊都要宣告。那件事做到了 —— 每個「意義色」在兩個主題都有值，而且**明暗是相反的**：

| token | 深色主題 | 淺色主題 |
|---|---|---|
| `--kt-info` | `#60a5fa` 淺藍 | `#1d4ed8` 深藍 |
| `--kt-status-done` | `#34d399` 淺綠 | `#047857` 深綠 |
| `--kt-status-failed` | `#fb7185` 淺粉 | `#be123c` 深紅 |
| `--kt-hit` | `#facc15` 淺琥珀 | `#a16207` 深琥珀 |

明暗相反是對的：兩個主題各自要在自己的底色上看得見。但**沒有人替「坐在這些填色上面的
文字」宣告過對應的墨色**。結果每個實心按鈕都自己寫死一個 `#fff` 或 `#000`，而寫死的墨色
在兩個主題裡必然有一邊是錯的：

- 寫死 `#fff` 的（PWA 安裝提示、ErrorBoundary 的重載按鈕、匯入面板的匯入鍵）：
  深色主題下白字配 `#60a5fa` 是 **2.54:1**。
- 寫死 `#000` 的（`shared/Button` 的 confirm 變體、跳過導覽連結、快速新增的加號）：
  淺色主題下黑字配 `#047857` 是 **3.83:1**、配 `#a16207` 是 **4.27:1**。

全部低於 AA 的 4.5:1，而且**不會有任何東西壞掉**——字還在，只是看不見。

同一次掃描還抓到第二種、更嚴重的形狀：把**表面上的**文字寫成 `#fff`
(`Integrations.module.css` 的 `.templateName`、agent 指示面板的取消鍵、
CyclePanel 的比較下拉)。那個位置的正確答案一直是 `--kt-ink`（深色白、淺色近黑），
寫死 `#fff` 在淺色主題就是白底白字，完全消失。

## Decision

新增 `--kt-on-fill`：深色主題 `#171717`、淺色主題 `#ffffff`。它是「坐在填色上的墨色」，
不是 `--kt-bg` 的別名——今天兩者剛好同值，是因為頁面底色本來就在同一條明暗軸的另一端；
如果底色哪天調整了，墨色要跟著填色走，不是跟著底色走。

`shared/Button` 的 confirm 變體改成 `color: var(--kt-on-fill)`，並新增 `ink` prop。
需要這個 prop 的原因很具體：`tone` 如果是一個 token，它會翻，墨色也該翻；但有兩個呼叫端
傳的是寫死的十六進位（依賴用 `#ffa42b`、成員用 `#818cf8`，兩個主題都一樣亮），
**固定的填色配不了會翻的墨色**，所以它們明確傳 `ink="#171717"`。

`--kt-info` 當底的三個按鈕、跳過導覽連結、快速新增鍵一併改用 `--kt-on-fill`；
三個「表面上的墨色」改用 `--kt-ink`。`StatCard` 的 `compact` 分支補上
`color || 'var(--kt-ink)'`，跟它自己的非 compact 分支一致——呼叫端本來傳 `color="#fff"`
就只是想說「用預設墨色」。

守衛 `src/__tests__/hardcodedInk.test.js` 掃 `.jsx` 與 `*.module.css`，
任何 `color: #fff|#000` 都要紅，除非檔案在名單上並附理由。名單只有一種理由：
墨色坐在**使用者自己選的顏色**上（身分頭像、專案圖示、accent 色票上的勾），
那裡白色是刻意的固定選擇，要做對需要的是亮度計算而不是一個 token。
名單另有一條反向檢查——被赦免的檔案如果不再含有那個字面值，測試也會紅，
免得一條不再成立的理由變成一個披著理由的破口。

守衛**不讀 `styles/global.css`**：那個檔案宣告兩套色盤，寫在
`[data-theme="light"]` 區塊裡的字面值是對的，要分辨得看選擇器而不是宣告本身。
這是刻意留下、寫明的邊界。

## Consequences

深色與淺色兩邊、五個填色（info / done / failed / hit / warning）的對比度全部從
不合格變成合格：深色 6.66–11.71，淺色 4.92–6.70。兩個固定十六進位的色調保留深墨色，
分別是 9.05 與 6.01（若讓它們吃預設會掉到 1.98 與 2.98）。

`Button` 多了一個 prop。這是誠實的成本：它讓「你的填色不會翻，所以你的墨色也不能翻」
這件事寫在呼叫端，而不是藏在一個猜測裡。

`#ffa42b` 和 `#818cf8` 本身仍然不是 token，在淺色主題下當**前景**色時對比也不足
（依賴晶片、成員晶片）。那是 ADR-0088 三家族之外的第四種顏色用途，要不要收進色盤
是一個設計決定，不在這次範圍內。

`styles/global.css` 內非主題範圍的字面墨色沒有被掃到。分辨它們需要逐條讀選擇器，
留給後續。
