# ADR-0156: 一條路徑要走得了兩個方向

## Status
Accepted

## Date
2026-09-08

## Context

使用者的原話是「點擊 Node 可以跳轉頁面、顯示路徑、返回上一層」，前面加了一句「我總覺得目前不太好用」。三件事看起來是三個新功能，實際上其中兩件已經蓋好一半——壞掉的是「哪一半」，而那正是這種抱怨最難自己講清楚的地方。

**「這個節點在哪裡打開」有三份規則，而且互相不同意。**

ADR-0094 把答案寫成 `utils/nodeHref.js`，ADR-0147 補上 `taskHref`(任務開在它的專案裡並 `?focus=` 那一列)。但 ADR-0065 更早留下了 `utils/containerRoute.js`，`pages/StructureMap.jsx` 又自己手寫了第三份 `jumpTo` switch。三份的差異不是風格問題:

| | `nodeHref` | `containerRoute` | `jumpTo` |
|---|---|---|---|
| goal | `/c/{id}` | `/goals`(清單) | `/goals`(清單) |
| identity | `/c/{id}` | `/c/{id}` | `/identities`(清單) |
| decision | `/n/{id}` | — | `/decisions`(清單) |
| task | `/projects/{p}?focus={id}` | — | `/projects/{p}`(無 focus) |

結構圖上雙擊一筆決策,會落在一頁 103 筆決策上。這不是「跳轉功能沒做」——它做了,而且回報成功——是**跳到了關於這一類東西的頁面,而不是關於被點的那一個東西的頁面**。同一個形狀在 `MapInspector` 裡再出現一次:一個身分底下的容器,連結是手寫的 `/projects/{id}`,而身分底下可以掛的容器型別不只 project(ADR-0095 之後身分自己也是容器),自訂容器就這樣落在一個關於「不存在的專案」的頁面上。

ADR-0155 才剛因為同一件事收掉三份手寫的關係清單。一份規則被畫成三份的代價從來不是重複的程式碼,是**其中兩份會慢慢說出不同的話,而且沒有任何一個測試會失敗**。

**「顯示路徑」有元件,但它不是麵包屑。**

`AncestryTrail`(ADR-0094)已經掛在專案頁、容器頁、節點頁、Data 頁和型別頁上,chip 也都可點。兩個缺口:

1. **路徑不含自己。**「CGCG › Pipeline dev」停在你的前一格。分隔號的工作是說「在……裡面」,最後一個分隔號後面沒有東西,它就沒有在說任何人。讀起來是一排浮著的標籤,不是一條路徑——這大概就是「總覺得不好用」但講不出哪裡不好用的來源。
2. **沒有上層時整條 `return null`。** 「這是一個根節點」和「這條路徑還沒回來」得到同一片空白,而且版面會跳。在列表的每一列上這是對的(一列本身就說得出它是什麼,定位器沒得定位就該消失);在一個「關於這一個節點」的頁面上這是錯的,而且它會**連著上一層的控制項一起帶走**——正好在唯一需要往上走的地方。

**「返回上一層」完全不存在。**

`NodePage` 有一顆按鈕,寫的是 `navigate(-1)`。那是瀏覽器上一頁,不是上一層:從搜尋結果點進來,按下去回到搜尋。`ProjectDetail` 那顆寫死 `navigate('/')`,標籤叫 "My Issues"——一個掛在 organization → identity 底下的專案,按「返回」直接掉回首頁。`ContainerView` 一顆都沒有。整個 app 唯一往上走的方式,是麵包屑上的 chip,而那正是上面第 2 點會讓它消失的東西。

## Decision

**一、`nodeHref` 是唯一的規則。** `containerRoute.js` 退役,`jumpTo` 的 switch 收成兩行(任務走 `taskHref`,其餘走 `nodeHref`),`MapInspector` 改吃傳進來的解析函式而不是自己拼字串。地圖節點自己的 `type` 是**繪圖分類**不是註冊表 key('project' 涵蓋所有容器角色、'custom' 涵蓋其餘),所以註冊表 key 以 `typeKey` 同行帶著,拿去問共用規則的是它。

goal 因此改開 `/c/{id}`(它帶 `container` 角色,`ContainerView` 本來就吃任何容器)。`/goals` 留著當清單。使用者裁決過這一項:點一個目標就該開那個目標。

**二、`AncestryTrail` 多一個 `self`,而那個 prop 就是兩種模式的分界。**

- 沒有 `self`:列表上的**定位器**,行為完全不變(沒東西可定位就消失、不畫上層控制項——一頁一百列就是一百個沒人會從清單按的控制項)。
- 有 `self`:這一頁自己的**麵包屑**。主體畫在路徑末端(不是連結,`aria-current="page"`),沒有上層時明說「未歸檔於任何位置」而不是消失,而且**只在答案回來之後才說**——請求還在路上時,只畫主體才是誠實的。

**三、上一層讀的是每條 trail 的最後一格,不是第一格**,而且讀的是**全部** trail 而不只是畫出來的那兩條:畫面能截斷,能去的地方不能。單一父節點是一個連結;多個父節點是一個列出每一個的選單,不是靜默挑第一個——路徑就畫在旁邊,這個控制項唯一不能做的事就是跟它矛盾。使用者裁決過這一項。

選單重用 `OverflowMenu`(多兩個 prop 讓它戴得上圖示和字)。理由不是省程式碼,是它已經帶著 portal-and-place:任何在「路由外框留有入場 `transform`」的頁面上就地定位的彈出層都會被裁切或位移(ADR-0122、ADR-0129),而那是每寫一個新下拉就會重新踩一次的坑。

**四、寫一個守門測試,然後被它抓到八個沒看見的抄本。**

`__tests__/nodeDestinationReach.test.js` 靜態掃描 `src/`,禁止任何檔案自己拼出 `/n/${…}`、
`/c/${…}` 或 `/projects/${…}`,並反向斷言那些真的會導航到節點的畫面確實呼叫了 `nodeHref`
——兩個方向都要,因為單獨任何一個在缺陷存在時都會通過(一頁可以沒有字面值也沒有連結,一個
helper 也可以存在而零呼叫端,那正是 ADR-0122 與 ADR-0132 的形狀)。

它抓到的不只三份,是八份。其中兩個是活的缺陷,不是抄寫:

- **`DecisionCard` 與 `GovernPicker` 把被治理的工作連到 `/n/{id}`。** `governs` 的另一端依角色
  篩選,可以是 task 也可以是 container(ADR-0122),所以一個被決策治理的**專案**,從決策這一側
  點過去會落在通用節點頁而不是專案頁。
- **命令面板搜到一個任務,開的是它的專案而沒有 `?focus=`。** ADR-0147 立的規則是任務開在專案裡
  並把那一列挑出來;面板是唯一沒有照做的入口,而它正是「我知道有這個任務,帶我去」的那個入口。

其餘六份(`TypeNodesPage`、`Goals`、`Dashboard`、`CommandPalette` 的自訂節點分支、
`GoverningDecisions`、`ProjectCard`)當時給的答案是對的,但是抄的——`TypeNodesPage` 那一行
甚至一字不差是 `nodeHref` 容器分支的重寫。

四個檔案留在允許清單裡,而且理由都不是「這個節點在哪裡打開」:`nodeHref.js` 自己、`App.jsx`
的路由宣告、`NodePage`/`MapInspector` 刻意提供的「以原始節點檢視」逃生口,以及
`ProjectDetail` 與 `NodeRelationsPanel` 在**只拿到 id、拿不到型別**時的退路——那個規則需要型別,
而那裡沒有型別可以給它。

**五、Explorer 每一列給一個看得見的「開啟」。** 單擊維持選取(右側面板靠它活著,合併掉會讓面板沒有東西可以填),但開啟不再是一個藏在 tooltip 字串尾巴的雙擊。使用者裁決過這一項。

`NodePage` 那顆 `navigate(-1)` 拿掉:現在有真的上一層了,一顆叫「返回」而實際上是瀏覽器上一頁的按鈕只會在旁邊說相反的話。

## Consequences

- 「這個節點在哪裡打開」再也不會有兩個答案。goal 的目的地變了,`ChildContainersPanel` 的測試跟著改,而那個斷言的舊值(`/goals`)正是這份 ADR 要修的缺陷本身。
- 麵包屑會把頁面標題再說一次(路徑末端一次、`<h1>` 一次)。這是刻意的:冗餘比歧義便宜,而且末端那一格用的是暗色純文字而不是 chip,所以它不會看起來像一個可以去的地方。
- 上一層在多父節點時是選單,所以「往上」偶爾要按兩下。正式站只有 16 個節點有兩個父,而那 16 個正是靜默挑一個會挑錯的那 16 個。
- `AncestryTrail` 現在有兩種模式,而模式由一個 prop 決定。這是一個真的分岔,不是設定旗標:定位器和麵包屑回答的是不同的問題,把它們合成一個「總是畫主體」的元件會讓每一列多一格永遠等於該列標題的文字。
- 地圖檢視器的開啟按鈕原本按型別各有一個標籤("Open Decisions"、"Open Personas"),那些字現在
  都指向錯的地方,所以收成一句 `structure.openSubject`(「開啟這個{{type}}」),型別名從註冊表
  讀(ADR-0058);而當它跟旁邊的「開啟節點頁」會去同一個地方時(決策就是),它根本不畫——
  兩顆按鈕一個目的地不是多一個選擇,是多一次猶豫。
- 地圖的 `jumpTo` 現在依賴 `typeKey` 隨節點同行。`graphStructure.js` 產出的容器與自訂節點都帶著它;身分和決策的 `type` 本身就是註冊表 key,所以 `node.typeKey || node.type` 覆蓋得到全部。新增一種地圖節點分類而忘了帶 `typeKey`,症狀是它落到 `/n/{id}`——一個真的頁面,只是比較弱的那一個。
